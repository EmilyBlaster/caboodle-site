## Anti-Patterns Verdict

**Fail.** Not for AI slop tells — the visual register (field-log mono sidebar, dossier numbering, lowercase wordmark, paper grain) is distinctive and on-brand. The fail is brand-rule drift: em dashes are scattered through code that ships to users, and "Caboodle Design" appears in title case in body copy. These are inconsistencies the site's own brand book bans explicitly. No gradient text, no hero-metric template, no identical card grids. Glassmorphism is present (6 `backdrop-filter` uses) but each is purposeful (sticky nav scroll state, image overlays) rather than decorative — keeping it.

- [x] **"Caboodle Design" in title case in body copy** — about.html:148 and index.html:601 (`I started Caboodle Design because I was tired...`), index.html:15 meta description (`Caboodle Design combines ethnographic research...`) — brand rule: always lowercase in running text. Lowercase to `caboodle design`. **Fixed 2026-05-03.** Also lowercased portrait alt text on about.html:79 and index.html:577.
- [ ] **No skip link on any page** — index.html, about.html, approach.html, work.html, labs.html, field-notes.html, resources.html, contact.html — keyboard-only users can't bypass the fixed nav and field-log to reach main content. Add `<a class="skip" href="#main">skip to content</a>` as the first child of `<body>` and an `id="main"` on the primary `<section>` or wrap content in `<main id="main">`. WCAG 2.4.1.
- [ ] **Mobile nav button missing ARIA state** — script.js:37–77 — the JS-injected hamburger button has no `aria-expanded`, no `aria-controls`, no announcement when the menu opens. - [ ] **`prefers-reduced-motion` not honored for View Transitions** — script.js:14–18 — the View Transitions API fires regardless of the user's motion preference. CSS at styles.css:296–301 honors reduced-motion but the JS path bypasses it. Wrap the transition trigger in `if (!matchMedia('(prefers-reduced-motion: reduce)').matches)`. WCAG 2.3.3 (AAA, but trivial to honor).

## Important (fix this week)

- [ ] **Field-notes thumbnail images render without `width`/`height`** — script.js:114–143, field-notes.html:127 — TikTok thumbs are injected dynamically with no dimensions, so each one shifts layout when it loads. Add intrinsic width/height attributes (or CSS `aspect-ratio`) to the `<img>` template. Hits CLS / Core Web Vitals.
- [ ] **Field-notes subscribe form uses `mailto:`** — field-notes.html:153–156 (`action="mailto:hello@caboodledesign.info"`) — email client prompts often fail silently on mobile, signups vanish. Switch to FormSubmit (the same flow contact.html:92 uses) or a Netlify form so addresses are captured.
- [ ] **9 of 66 images missing `loading="lazy"`** — spread across pages; grep `<img ` vs `loading="lazy"` shows the gap — easy wins on mobile data and initial paint. Add `loading="lazy"` and `decoding="async"` to non-hero images.
- [ ] **Mobile hamburger injected post-DOM** — script.js:37–77 — desktop nav flashes briefly on slow connections before JS replaces it with the mobile button. Move the button into the HTML markup, hide it behind a CSS media query, and let JS only attach the open/close listener.
- [ ] **Body-wide SVG turbulence grain** — styles.css:112–119 — `feTurbulence` runs as a fullscreen `body::before` filter on every page, every paint. Acceptable on desktop, costly on low-end mobile. Consider rendering once to a static PNG/WebP and using that as a tiled background, keeping the SVG version behind a `(min-width: 1024px)` media query.
- [ ] **Form honeypot uses `display:` instead of proper anti-spam markup** — contact.html:98 — visible to assistive tech if styles fail. Use `tabindex="-1"`, `autocomplete="off"`, and `aria-hidden="true"` together so the field is consistently invisible to humans and bots without breaking screen readers.
- [ ] **Carousel announces no slide changes** — script.js:304–348 — keyboard navigation works but the active slide isn't communicated. Wrap the active slide's caption (or a sr-only sibling) in `aria-live="polite"` so screen readers hear "slide 2 of 5: gitlab dossier" on change.
- [ ] **Lime-on-paper contrast risk** — styles.css uses `color: var(--lime)` in 18+ rules. Most sit on `--ink` (dark) backgrounds where contrast is fine, but audit each occurrence to confirm none land on `--paper` (#f2efe8) where lime is ~2.8:1 against light. Rules to spot-check: 856, 1025, 1111, 1196, 1225, 1240, 1362, 1581, 1862. If any are on light backgrounds, swap to `--blue-deep` or `--magenta` for that role.
